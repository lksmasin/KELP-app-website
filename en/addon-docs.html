Supported Sources in KELP

KELP operates exclusively through general, open protocols and ships with no built-in media or pre-installed add-ons. Below is an overview of all supported source types; the rest of this page documents how to write declarative JSON add-ons.

Protocol / SourceSetup in KELPUse Case
STREMIO_V3URL to manifest.json or stremio://Standard Stremio v3 add-ons (catalogs, streams, subtitles).
DECLARATIVE_JSONURL or local .json definitionSafe declarative HTTP/XML/JSON pipeline with no executable code (specification below).
WEBDAVServer URL + optional credentialsPersonal NAS or WebDAV storage.
LOCAL_DISKLocal folder pickerLocal video files and drives (indexed directly on the device).
M3U / XTREAM / XMLTVLive TV → SourcesLive channels, channel groups, XMLTV EPG guide, and archive catch-up.

Introduction

Out of the box, KELP contains no stream sources and no built-in access to any storage provider. All functionality for searching and playing files from external services is provided by add-ons imported by the user — from a URL or a local JSON file.

An add-on is a purely declarative JSON file that describes:

  • Manifest — add-on metadata (name, author, version, capabilities)
  • Authentication — how to sign in to the service
  • Search — how to search for files by query
  • Streaming — how to resolve a direct stream URL

An add-on contains no executable code. It is a declarative pipeline interpreted by the application's built-in Addon Engine.

The add-on system is designed to be maximally safe. A JSON definition cannot execute arbitrary code — it can only run predefined actions (HTTP requests, hashing, regex).

Add-on Lifecycle

  1. Import — the user enters a URL or chooses a JSON file. AddonImporter downloads/reads and validates the JSON.
  2. Parsing — AddonDefinition.fromJson() parses the JSON into structured objects (manifest, auth, search, streamUrl).
  3. Registration — an AddonEngine instance is created and registered in AddonRegistry.
  4. Persistence — the raw JSON is stored in the SQLite table installed_addons so the add-on survives restarts.
  5. Authentication — the user enters credentials → the engine executes the auth.login pipeline.
  6. Usage — during search the engine runs the search pipeline; on playback it runs the streamUrl pipeline.
  7. Restore — on app startup AddonRegistryManager restores all saved definitions from SQLite and reinitializes engines and auth state.

Root JSON Structure

Each add-on is a single JSON file with the following top-level structure:

JSON{
  "manifest": { ... },
  "auth": { ... },
  "search": { ... },
  "streamUrl": { ... }
}
KeyTypeRequiredDescription
manifestObjectYesAdd-on metadata — identification, version, capabilities.
authObjectNoAuthentication flow definition. If omitted, the add-on requires no sign-in.
searchObjectYesPipeline for searching files.
streamUrlObjectYesPipeline for resolving a direct stream URL.

Section manifest

The manifest holds all metadata about the add-on. These fields are displayed in the application settings.

JSON{
  "manifest": {
    "id": "my-addon",
    "name": "My Add-on",
    "version": "1.0.0",
    "description": "Description of what this add-on does.",
    "author": "Jane Doe",
    "type": "api",
    "capabilities": ["search", "auth", "directStream"],
    "homeUrl": "https://example.com",
    "iconUrl": "https://example.com/icon.png"
  }
}
FieldTypeRequiredDescription
idStringYesUnique add-on identifier used internally to store state and credentials. Recommended format: kebab-case without spaces or diacritics (e.g., "my-nas", "my-addon").
nameStringYesDisplay name shown in the UI (e.g., "My Add-on").
versionStringNoAdd-on version in semver format. Default: "1.0.0".
descriptionStringNoShort description of the add-on.
authorStringNoAuthor name. Default: "Unknown".
typeStringNoAdd-on type: "api", "scraper", or "hybrid". Default: "api". See Addon Types.
capabilitiesArray<String>NoList of capabilities. Default: ["search"]. See Capabilities.
homeUrlStringNoHomepage URL of the service.
iconUrlStringNoIcon URL displayed in the UI.

The id field must be unique across all installed add-ons. Attempting to import an add-on with an existing id will be rejected.

Section auth

Defines the authentication flow — which form fields the user fills in, and which steps execute for login, session verification, and logout.

JSON{
  "auth": {
    "type": "credentials",
    "fields": [
      {
        "key": "username",
        "label": "Username",
        "hint": "Enter your username",
        "isSecret": false,
        "required": true
      },
      {
        "key": "password",
        "label": "Password",
        "hint": "Enter your password",
        "isSecret": true,
        "required": true
      }
    ],
    "login": [ ... ],
    "check": [ ... ],
    "logout": [ ... ]
  }
}

Field Definitions (fields)

Fields define the form shown to the user in Settings. Each key becomes a runtime variable name — see Variables.

FieldTypeRequiredDescription
keyStringYesUnique field key. Becomes the runtime variable name (e.g., "username", "api_key").

Login / Check / Logout Pipelines

Each of these sections is an array of steps — see Actions.

PipelineWhen It RunsRequired
loginWhen the user fills in credentials and confirms sign-in.No (login will not run without it)
checkWhen the engine verifies whether the current session is still valid.No (fallback: checks that token exists)
logoutWhen the user signs out.No

If no check pipeline is defined, the engine falls back to checking whether a non-empty runtime variable named token exists. It is therefore recommended to store the session token under the variable key "token".

Section search

Defines the pipeline for searching files. Its output must be a list of items (see Result Lists).

JSON{
  "search": {
    "steps": [
      {
        "action": "http",
        "method": "POST",
        "url": "https://api.example.com/search",
        "contentType": "application/x-www-form-urlencoded",
        "body": "q={{query}}&limit=100&token={{token}}",
        "responseType": "xml",
        "listElement": "file",
        "itemMapping": {
          "title": "name",
          "size": "size",
          "link": "ident"
        }
      }
    ]
  }
}

The search pipeline automatically has access to the following variables:

VariableValue
{{query}}Search query text entered by the user.
{{page}}Page number (1-based) for paginated results.
{{token}}Authentication token (when the add-on uses auth).

Item Mapping

The key parameter on the HTTP step in a search pipeline is itemMapping, which maps fields from the response to KELP's internal item structure:

Target FieldRequiredDescription
title or nameYesFile name / title. The engine looks for title first, then name.
sizeNoFile size in bytes (integer). Automatically formatted to human-readable units (MB/GB).
link or urlYesUnique item identifier. Passed to the streamUrl pipeline as {{identifier}}.

Section streamUrl

Defines the pipeline that resolves a direct streaming URL for the chosen file.

JSON{
  "streamUrl": {
    "steps": [
      {
        "action": "http",
        "method": "POST",
        "url": "https://api.example.com/file_link",
        "contentType": "application/x-www-form-urlencoded",
        "body": "ident={{identifier}}&token={{token}}",
        "responseType": "xml",
        "outputs": {
          "stream_url": "link"
        }
      }
    ],
    "result": "{{stream_url}}",
    "headers": {
      "Referer": "https://example.com/",
      "User-Agent": "KELP/1.0",
      "Authorization": "Bearer {{token}}"
    }
  }
}
FieldTypeDescription
stepsArray<Step>Step pipeline that obtains the stream URL.
resultStringTemplate referencing the variable holding the final stream URL. Typically "{{stream_url}}".
headersObjectNo Extra HTTP headers sent by the player while streaming. Supports template interpolation. Typically Referer, User-Agent, Cookie, or Authorization.

The streamUrl pipeline automatically has access to:

VariableValue
{{identifier}}File identifier from search results (the value of link/url in itemMapping).
{{token}}Authentication token.

Action: http

Executes an HTTP request. The primary and most frequently used action.

JSON{
  "action": "http",
  "method": "POST",
  "url": "https://api.example.com/endpoint",
  "contentType": "application/x-www-form-urlencoded",
  "body": "param1={{value1}}¶m2={{value2}}",
  "responseType": "xml",
  "headers": {
    "Authorization": "Bearer {{token}}",
    "X-Custom": "value"
  },
  "outputs": {
    "my_variable": "xml_tag_name"
  }
}
ParameterTypeDefaultDescription
actionString—Must be "http".
methodString"GET"HTTP method: "GET" or "POST".
urlString—Endpoint URL. Supports interpolation.
contentTypeString—Value of the Content-Type header.
bodyString—Request body (for POST). Supports interpolation.
responseTypeString"xml"Response format: "xml" or "json". Controls how outputs are parsed.
headersObject{}Custom HTTP headers. Values support interpolation.
outputsObject—Mapping: { "variable_name": "path_in_response" }. See XML / JSON parsing.
listElementString—Search only: name or path of the repeating list element in the response.
itemMappingObject—Search only: field mapping for each item. See Result Lists.

If an HTTP step returns any status other than 200, the entire pipeline fails. The engine does not follow redirects or accept other 2xx codes.

Action: md5crypt

Computes a Unix MD5-crypt hash ($1$salt$hash format). Typically required by legacy APIs for password hashing.

JSON{
  "action": "md5crypt",
  "input": "{{password}}",
  "salt": "{{salt}}",
  "output": "crypted_password"
}
ParameterTypeDescription
inputStringInput string (typically a password). Supports interpolation.
saltStringSalt value. Supports interpolation. Max 8 characters.
outputStringVariable name to store the resulting hash.

Example output: $1$abcdefgh$k4x3gHwmKj1vC0B.Xr5M/.

Action: sha1

Computes the SHA-1 hash of the input string.

JSON{
  "action": "sha1",
  "input": "{{crypted_password}}",
  "output": "hashed_password"
}
ParameterTypeDescription
inputStringInput text. Supports interpolation.
outputStringVariable name for the hex-encoded digest.

Example output: a94a8fe5ccb19ba61c4c0873d391e987982fbbd3

Action: md5

Computes the MD5 hash of the input string.

JSON{
  "action": "md5",
  "input": "{{some_value}}",
  "output": "md5_hash"
}
ParameterTypeDescription
inputStringInput text. Supports interpolation.
outputStringVariable name for the hex-encoded digest.

Example output: 5d41402abc4b2a76b9719d911017c592

Action: assert

Compares a runtime variable against an expected value. If they do not match, the pipeline fails and subsequent steps are skipped.

JSON{
  "action": "assert",
  "variable": "login_status",
  "equals": "OK"
}
ParameterTypeDescription
variableStringName of the runtime variable to check.
equalsStringExpected value.

Assert is essential for validating API responses. Place it immediately after an HTTP step to verify that the operation (login, search) succeeded.

Action: clear

Removes runtime variables from the engine's state.

JSON{
  "action": "clear",
  "variables": ["token", "salt", "crypted_password", "temp_value"]
}
ParameterTypeDescription
variablesArray<String>List of variable names to remove.

Typically used in the logout pipeline to clear session tokens.

Action: regex

Extracts text from a variable using a regular expression.

JSON{
  "action": "regex",
  "input": "{{_response}}",
  "pattern": "href=\"(https://[^\"]+\\.mp4)\"",
  "group": 1,
  "output": "video_url"
}
ParameterTypeDefaultDescription
inputString—Input text. Supports interpolation. Typically {{_response}}.
patternString—Regular expression (PCRE / Java Regex syntax).
groupInteger1Capture group index to extract.
outputString—Variable name for the extracted match.
optionalBooleanfalseWhen true, a failure does not abort the pipeline — execution continues with the next step. See Optional Steps.

If the regex finds no match and the step is not marked "optional": true, the pipeline fails. Make sure the pattern matches the response format or chain optional fallback steps.

Optional Steps (optional)

Any step in a pipeline can be marked optional by adding "optional": true. If an optional step fails, the pipeline continues to the next step instead of aborting.

For the regex action specifically: if its output variable was already populated by an earlier step, the optional regex is skipped. This makes fallback chaining clean and straightforward:

Example — fallback chain{
  "steps": [
    { "action": "http", "method": "GET", "url": "https://api.example.com/{{identifier}}", "responseType": "json" },
    {
      "action": "regex",
      "input": "{{_response}}",
      "pattern": "\"name\":\\s*\"([^\"]+\\.mp4)\",\\s*\"source\":\\s*\"original\"",
      "group": 1,
      "output": "video_file",
      "optional": true
    },
    {
      "action": "regex",
      "input": "{{_response}}",
      "pattern": "\"name\":\\s*\"([^/\"]+\\.mp4)\"",
      "group": 1,
      "output": "video_file",
      "optional": true
    }
  ],
  "result": "https://example.com/download/{{identifier}}/{{video_file|urlencode}}"
}

In this example, the engine first searches for an MP4 file with source: "original". If none is found, the second regex falls back to any MP4. If the first regex succeeds, the second is skipped because video_file is already set.

The optional flag works on all actions (http, regex, assert, etc.), not only on regex.

Action: set

Assigns a value directly to a variable. Useful for composing strings from multiple variables or setting default values.

JSON{
  "action": "set",
  "output": "full_url",
  "value": "https://cdn.example.com/{{path}}/{{filename|urlencode}}"
}
ParameterTypeDescription
outputStringName of the variable to write to.
valueStringValue expression (supports interpolation and filters).

Action: parallel

Runs multiple independent steps concurrently. All nested steps execute in parallel, and the action succeeds if all of them succeed.

JSON{
  "action": "parallel",
  "steps": [
    {
      "action": "http",
      "method": "GET",
      "url": "https://api.example.com/metadata/{{identifier}}",
      "responseType": "json",
      "outputs": { "meta_title": "title" }
    },
    {
      "action": "http",
      "method": "GET",
      "url": "https://api.example.com/files/{{identifier}}",
      "responseType": "json",
      "outputs": { "file_url": "url" }
    }
  ]
}
ParameterTypeDescription
stepsArray<Step>List of steps to execute concurrently. Each item is a standard step definition.

Parallel steps must not depend on each other's outputs. If step B relies on an output from step A, execute them sequentially (outside parallel).

Variables

Addon Engine maintains a runtime variable map (Map<String, String>) populated from:

  • Credentials — keys from auth.fields (e.g., username, password, api_key)
  • HTTP outputs — values extracted from API responses
  • Crypto steps — hash outputs (md5crypt, sha1, md5)
  • Regex — extracted substrings
  • Automatic — query, page, identifier

Interpolation {{variable}}

Anywhere a parameter takes a string value, double-brace interpolation can be used:

Example"url": "https://api.example.com/search?q={{query}}&token={{token}}"
"body": "username={{username}}&password={{hashed_password}}"
"input": "{{crypted}}"

The engine replaces every {{name}} placeholder with its current value from the variable map. Unknown variables evaluate to an empty string.

Filters {{variable|filter}}

Append a pipe (|) and filter name after a variable to transform its value before insertion:

Example"url": "https://api.example.com/search?q={{query|urlencode}}"
"body": "token={{token|base64}}"
"header": "{{api_key|uppercase}}"
FilterDescriptionInput → Output Example
urlencodeURL percent-encoding. Recommended for {{query}} in URLs.Movie 2026 → Movie%202026
base64Base64 encoding.hello → aGVsbG8=
lowercaseConverts to lowercase.HELLO → hello
uppercaseConverts to uppercase.hello → HELLO
trimTrims leading and trailing whitespace. hello → hello
htmldecodeDecodes HTML entities.&amp; &lt; → & <
lengthString length (returns a number string).hello → 5
reverseReverses the string characters.hello → olleh
timestampReturns current Unix timestamp in seconds (ignores variable value).→ 1741700000
timestamp_msReturns current Unix timestamp in milliseconds.→ 1741700000000

If a filter name is unrecognized, the value is inserted without transformation.

XML Parsing

With "responseType": "xml", the engine extracts values by XML tag name.

XML response<response>
  <status>OK</status>
  <token>abc123xyz</token>
  <user_id>42</user_id>
</response>
outputs"outputs": {
  "status_var": "status",
  "token": "token",
  "uid": "user_id"
}

Result: status_var = "OK", token = "abc123xyz", uid = "42"

The XML parser supports tags with attributes — e.g., <file id="123">...</file> matches when looking up the file tag. To extract attributes, use the tag@attr notation in mappings (see below).

To extract attributes from XML tags, use tag@attribute notation:

XML with attributes<files>
  <file id="abc123" type="video">Movie.mp4</file>
  <file id="def456" type="subtitle">Movie.srt</file>
</files>
itemMapping"itemMapping": {
  "title": "file",
  "link": "file@id",
  "type": "file@type"
}

Result: link = "abc123", type = "video". Using @attr (without a tag name) extracts an attribute from the parent element.

JSON Parsing

With "responseType": "json", the engine uses dot notation to navigate JSON objects.

JSON response{
  "status": "ok",
  "data": {
    "token": "xyz789",
    "user": {
      "id": 42,
      "name": "Alex"
    }
  }
}
outputs"outputs": {
  "my_token": "data.token",
  "user_name": "data.user.name",
  "user_id": "data.user.id"
}

Result: my_token = "xyz789", user_name = "Alex", user_id = "42"

To access array elements, use bracket or numeric index notation:

JSON path with array"outputs": {
  "first_item": "results[0].name",
  "first_item_alt": "results.0.name"
}

To filter an array by field value, use [?(@.key=='value')]:

JSON path with filter"outputs": {
  "video_file": "files[?(@.source=='original')].name"
}

The filter scans the files array, picks the first element where source equals "original", and extracts its name.

Nested paths also work inside search itemMapping: e.g., "title": "metadata.title" or "id": "files[0].id".

Result Lists (List Parsing)

In a search pipeline, an HTTP step with listElement identifies repeating items in the response:

XML List

XML response<response>
  <status>OK</status>
  <file>
    <name>Movie.2024.EN.mkv</name>
    <size>1536000000</size>
    <ident>abc123</ident>
  </file>
  <file>
    <name>Movie.2024.4K.mp4</name>
    <size>987000000</size>
    <ident>def456</ident>
  </file>
</response>
Search step{
  "action": "http",
  "method": "POST",
  "url": "https://api.example.com/search",
  "body": "q={{query}}&token={{token}}",
  "responseType": "xml",
  "listElement": "file",
  "itemMapping": {
    "title": "name",
    "size": "size",
    "link": "ident"
  }
}

The engine locates every <file>...</file> block and extracts name, size, and ident according to the mapping.

JSON List

JSON response{
  "status": "ok",
  "results": [
    { "title": "Movie.2024.EN.mkv", "filesize": 1536000000, "id": "abc123" },
    { "title": "Movie.2024.4K.mp4", "filesize": 987000000, "id": "def456" }
  ]
}
Search step{
  "action": "http",
  "method": "GET",
  "url": "https://api.example.com/search?q={{query|urlencode}}",
  "responseType": "json",
  "listElement": "results",
  "itemMapping": {
    "title": "title",
    "size": "filesize",
    "link": "id"
  }
}

For JSON responses, listElement is a dot-notation path to an array of objects. Each object's fields are extracted using the keys in itemMapping.

public-api.json{
  "manifest": {
    "id": "public-videos",
    "name": "Public Videos API",
    "version": "1.0.0",
    "description": "Public API for searching videos.",
    "author": "Community",
    "type": "api",
    "capabilities": ["search", "directStream"]
  },
  "search": {
    "steps": [

Example: Token-Based Auth with Regex

An add-on extracting a session token from an HTML response using a regular expression:

scraper-addon.json{
  "manifest": {
    "id": "my-scraper",
    "name": "My Scraper",
    "version": "1.0.0",
    "description": "Sample scraper add-on using regex extraction.",
    "author": "Community",
    "type": "scraper",
    "capabilities": ["search", "auth", "directStream"]
  },
  "auth": {
    "type": "credentials",
    "fields": [
      {
        "key": "email",
        "label": "E-mail",
        "isSecret": false,
        "required": true
      },
      {
        "key": "password",
        "label": "Password",
        "isSecret": true,
        "required": true
      }
    ],
    "login": [
      {
        "action": "http",
        "method": "POST",
        "url": "https://example.com/login",
        "contentType": "application/x-www-form-urlencoded",
        "body": "email={{email}}&password={{password}}",
        "responseType": "xml"
      },
      {
        "action": "regex",
        "input": "{{_response}}",
        "pattern": "session_token[\"']?\\s*[:=]\\s*[\"']([a-f0-9]{32})[\"']",
        "group": 1,
        "output": "token"
      }
    ]
  },
  "search": {
    "steps": [
      {
        "action": "http",
        "method": "GET",
        "url": "https://example.com/search?q={{query|urlencode}}",
        "responseType": "xml",
        "headers": {
          "Cookie": "session={{token}}"
        }
      },
      {
        "action": "regex",
        "input": "{{_response}}",
        "pattern": "data-results='(\\[.*?\\])'",
        "group": 1,
        "output": "json_results"
      },
      {
        "action": "http",
        "method": "GET",
        "url": "https://example.com/api/parse-results",
        "responseType": "json",
        "headers": {
          "X-Data": "{{json_results}}"
        },
        "listElement": "items",
        "itemMapping": {
          "title": "name",
          "size": "size",
          "link": "url"
        }
      }
    ]
  },
  "streamUrl": {
    "steps": [
      {
        "action": "http",
        "method": "GET",
        "url": "{{identifier}}",
        "responseType": "xml",
        "headers": {
          "Cookie": "session={{token}}"
        }
      },
      {
        "action": "regex",
        "input": "{{_response}}",
        "pattern": "source\\s+src=[\"'](https://[^\"']+\\.mp4)[\"']",
        "group": 1,
        "output": "stream_url"
      }
    ],
    "result": "{{stream_url}}"
  }
}

Capabilities

ValueDescription
"search"The add-on supports file search. Required — every add-on must support search.
"auth"The add-on requires authentication (sign-in).
"directStream"The add-on returns direct stream URLs (not redirects).
"subtitles"The add-on provides subtitles (reserved for future use).
"download"The add-on supports file downloads (reserved for future use).

Addon Types

ValueDescription
"api"Data is fetched through a structured API (REST, XML-RPC, GraphQL, etc.).
"scraper"Data is extracted by parsing HTML pages (using regex).
"hybrid"Combination of both — some endpoints use an API while others rely on scraping.

The add-on type is informational metadata only — it does not change engine behavior. The engine runs steps identically regardless of type.

Error States

The engine can fail in the following situations:

SituationBehavior
HTTP step returns a status other than 200Pipeline stops; the step returns false.
Assert fails (value != expected)Pipeline stops; the entire flow returns false.
Regex finds no matchPipeline stops; the step returns false.
Unknown actionPipeline stops; a warning is logged to the console.
HTTP request timeoutEngine catches the exception; the step returns false.
Invalid JSON fileImport fails and displays an error message.
Duplicate add-on IDImport is rejected with a warning.

Limitations

  • HTTP GET and POST only — other methods (PUT, DELETE, PATCH) are not supported.
  • No JavaScript — add-ons cannot run JS code (unlike browser extensions).
  • XML namespaces — the parser handles tags with attributes, but does not support XML namespaces (e.g., ns:tag).
  • JSONPath without wildcards — expressions like data.*.name are unsupported. Indexes [0] and filters [?(@.key=='val')] are supported.
  • MD5-crypt salt max 8 chars — longer salts are truncated.
  • No automatic cookies — the engine does not manage cookies automatically. Tokens must be passed explicitly.
  • No redirects — the HTTP client does not automatically follow 3xx redirects when parsing responses.
  • String-only variables — all runtime values are strings with no numeric arithmetic.
  • One search page = one HTTP step with listElement — results cannot be merged across multiple calls within one search step (though parallel can be used for independent calls).
