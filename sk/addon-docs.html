Podporované zdroje v KELP

KELP pracuje výhradne cez všeobecné otvorené protokoly a v základnej inštalácii neobsahuje žiadny obsah ani predinštalované doplnky. Nižšie je prehľad všetkých podporovaných typov zdrojov; táto stránka podrobne popisuje tvorbu deklaratívnych JSON doplnkov.

Protokol / zdrojInštalácia v KELPPoužitie
STREMIO_V3URL na manifest.json alebo stremio://Štandardné Stremio v3 doplnky (katalógy, streamy, titulky).
DECLARATIVE_JSONURL alebo lokálna .json definíciaBezpečná deklaratívna HTTP/XML/JSON pipeline bez spustiteľného kódu (špecifikácia nižšie).
WEBDAVAdresa servera + voliteľné prihlásenieVlastný NAS alebo WebDAV úložisko.
LOCAL_DISKVýber lokálneho priečinkaLokálne video súbory a disky (indexácia priamo na zariadení).
M3U / XTREAM / XMLTVSekcia Živá TV → ZdrojeŽivé vysielanie, skupiny kanálov, EPG program a spätné prehratie z archívu.

Úvod

Aplikácia KELP v základnej inštalácii neobsahuje žiadny zdroj streamov ani prístup k žiadnemu úložisku. Všetka funkcionalita spojená s vyhľadávaním a prehrávaním súborov z externých služieb je zabezpečená doplnkami (addonmi), ktoré si používateľ importuje sám — z URL adresy alebo lokálneho JSON súboru.

Doplnok je čisto deklaratívny JSON súbor, ktorý popisuje:

  • Manifest — metadáta doplnku (názov, autor, verzia, schopnosti)
  • Autentifikácia — ako sa prihlásiť k danej službe
  • Vyhľadávanie — ako vyhľadať súbory podľa dopytu
  • Streamovanie — ako získať priamy odkaz na stream

Doplnok neobsahuje žiadny spustiteľný kód. Ide o deklaratívnu pipeline, ktorú interpretuje vstavaný Addon Engine aplikácie.

Addon systém je navrhnutý tak, aby bol maximálne bezpečný. JSON definícia nemôže spustiť ľubovoľný kód — môže vykonávať iba vopred definované akcie (HTTP požiadavky, hashovanie, regex).

Architektúra

Addon systém sa skladá z nasledujúcich komponentov:

KELP App
AddonStore
(persistence)
AddonRegistry
(runtime)
AddonImporter
(URL / file)
AddonEngine
(JSON interpreter / runner)
AddonInterface
(abstraktný API kontrakt)
KomponentPopis
AddonDefinitionDátový model parsovaný z JSON súboru. Obsahuje sekcie manifest, auth, search a streamUrl.
AddonEngineInterpreter, ktorý implementuje AddonInterface na základe JSON definície. Vykonáva pipeline krokov (steps).
AddonStorePerzistentné úložisko (SQLite databáza installed_addons). Ukladá raw JSON definície, takže prežijú reštart aplikácie.
AddonRegistrySingleton register bežiacich doplnkov. Spravuje stav, prihlasovacie údaje a aktívne doplnky.
AddonImporterImport z URL (HTTP stiahnutie) alebo z lokálneho súboru (výber súboru).
AddonInterfaceAbstraktný kontrakt definujúci metódy: authenticate, search, getStreamUrl a pod.

Životný cyklus doplnku

  1. Import — používateľ zadá URL alebo vyberie JSON súbor. AddonImporter stiahne/prečíta JSON a zvaliduje ho.
  2. Parsovanie — AddonDefinition.fromJson() rozloží JSON na štruktúrované objekty (manifest, auth, search, streamUrl).
  3. Registrácia — vytvorí sa inštancia AddonEngine a zaregistruje sa do AddonRegistry.
  4. Perzistencia — raw JSON sa uloží do SQLite tabuľky installed_addons, aby doplnok prežil reštart.
  5. Autentifikácia — používateľ vyplní prihlasovacie údaje → engine spustí auth.login pipeline.
  6. Použitie — pri vyhľadávaní engine spustí search pipeline, pri prehrávaní streamUrl pipeline.
  7. Obnova — pri štarte aplikácie AddonRegistryManager obnoví všetky uložené definície z SQLite a obnoví enginy aj autentifikáciu.

Koreňová štruktúra JSON

Každý doplnok je jeden JSON súbor s nasledujúcou koreňovou štruktúrou:

JSON{
  "manifest": { ... },
  "auth": { ... },
  "search": { ... },
  "streamUrl": { ... }
}
KľúčTypPovinnýPopis
manifestObjectÁnoMetadáta doplnku — identifikácia, verzia, schopnosti.
authObjectNieDefinícia autentifikačného flow. Ak chýba, doplnok nevyžaduje prihlásenie.
searchObjectÁnoPipeline na vyhľadávanie súborov.
streamUrlObjectÁnoPipeline na získanie priameho odkazu na stream.

Sekcia manifest

Manifest obsahuje všetky metadáta o doplnku. Tieto informácie sa zobrazujú v nastaveniach aplikácie.

JSON{
  "manifest": {
    "id": "moj-doplnok",
    "name": "Môj doplnok",
    "version": "1.0.0",
    "description": "Popis toho, čo doplnok robí.",
    "author": "Ján Novák",
    "type": "api",
    "capabilities": ["search", "auth", "directStream"],
    "homeUrl": "https://example.com",
    "iconUrl": "https://example.com/icon.png"
  }
}
PoleTypPovinnýPopis
idStringÁnoUnikátny identifikátor doplnku. Používa sa interne na ukladanie stavu, prihlasovacích údajov a pod. Odporúčaný formát: kebab-case bez medzier a diakritiky (napr. "moj-nas", "moj-doplnok").
nameStringÁnoZobrazovaný názov doplnku v UI (napr. "Môj doplnok").
versionStringNieVerzia doplnku vo formáte semver. Predvolené: "1.0.0".
descriptionStringNieKrátky popis doplnku.
authorStringNieMeno autora doplnku. Predvolené: "Unknown".
typeStringNieTyp doplnku: "api", "scraper" alebo "hybrid". Predvolené: "api". Pozri Addon Types.
capabilitiesArray<String>NieZoznam schopností doplnku. Predvolené: ["search"]. Pozri Capabilities.
homeUrlStringNieURL domovskej stránky služby.
iconUrlStringNieURL ikony doplnku (zobrazuje sa v UI).

Pole id musí byť naprieč všetkými doplnkami unikátne. Ak sa pokúsite importovať doplnok s rovnakým id ako už nainštalovaný, import bude odmietnutý.

Sekcia auth

Definuje autentifikačný flow — teda aké polia používateľ vyplní a aké kroky sa vykonajú na prihlásenie, overenie stavu a odhlásenie.

JSON{
  "auth": {
    "type": "credentials",
    "fields": [
      {
        "key": "username",
        "label": "Používateľské meno",
        "hint": "Zadajte používateľské meno",
        "isSecret": false,
        "required": true
      },
      {
        "key": "password",
        "label": "Heslo",
        "hint": "Zadajte heslo",
        "isSecret": true,
        "required": true
      }
    ],
    "login": [ ... ],
    "check": [ ... ],
    "logout": [ ... ]
  }
}

Typy autentifikácie

Hodnota typePopis
"none"Doplnok nevyžaduje prihlásenie. Sekcia auth môže úplne chýbať.
"credentials"Klasické prihlásenie používateľským menom a heslom.
"token"Autentifikácia API tokenom / kľúčom.
"oauth"OAuth2 flow (rezervované pre budúce použitie).

Definícia polí (fields)

Polia definujú formulár, ktorý sa zobrazí používateľovi v nastaveniach. Kľúč (key) sa použije ako názov premennej — pozri Premenné.

PoleTypPovinnýPopis
keyStringÁnoUnikátny kľúč poľa. Stane sa názvom runtime premennej (napr. "username", "api_key").
labelStringÁnoPopisok zobrazený v UI.
hintStringNiePlaceholder / nápoveda v textovom poli.
isSecretBooleanNieZobraziť ako heslo (skryté znaky). Predvolené: false.
requiredBooleanNieJe pole povinné? Predvolené: true.

Login / Check / Logout pipelines

Každá z týchto sekcií je pole krokov (steps) — pozri Akcie.

PipelineKedy sa spúšťaPovinný
loginKeď používateľ vyplní prihlasovacie údaje a potvrdí prihlásenie.Nie (bez neho sa však prihlásenie nespustí)
checkKeď engine potrebuje overiť, či je relácia stále platná.Nie (fallback: kontrola existencie premennej token)
logoutKeď sa používateľ odhlási.Nie

Ak pipeline check nie je definovaná, engine ako fallback skontroluje, či existuje neprázdna runtime premenná token. Preto sa odporúča, aby login kroky uložili token do premennej s kľúčom "token".

Sekcia search

Definuje pipeline na vyhľadávanie súborov. Výsledkom musí byť zoznam položiek (pozri Zoznam výsledkov).

JSON{
  "search": {
    "steps": [
      {
        "action": "http",
        "method": "POST",
        "url": "https://api.example.com/search",
        "contentType": "application/x-www-form-urlencoded",
        "body": "q={{query}}&limit=100&token={{token}}",
        "responseType": "xml",
        "listElement": "file",
        "itemMapping": {
          "title": "name",
          "size": "size",
          "link": "ident"
        }
      }
    ]
  }
}

Search pipeline má prístup k týmto automaticky dostupným premenným:

PremennáHodnota
{{query}}Hľadaný text zadaný používateľom.
{{page}}Číslo stránky (od 1) pre stránkovanie výsledkov.
{{token}}Autentifikačný token (ak doplnok vyžaduje auth).

Item Mapping

Kľúčový parameter HTTP kroku v search pipeline je itemMapping, ktorý mapuje polia z odpovede na internú štruktúru:

Cieľové polePovinnýPopis
title alebo nameÁnoNázov súboru. Engine najprv hľadá title, potom name.
sizeNieVeľkosť súboru v bajtoch (celé číslo). Engine automaticky prevedie na čitateľný formát (MB/GB).
link alebo urlÁnoUnikátny identifikátor položky. Bude odovzdaný do streamUrl pipeline ako {{identifier}}.

Sekcia streamUrl

Definuje pipeline na získanie priameho streamovacieho odkazu zo zvoleného súboru.

JSON{
  "streamUrl": {
    "steps": [
      {
        "action": "http",
        "method": "POST",
        "url": "https://api.example.com/file_link",
        "contentType": "application/x-www-form-urlencoded",
        "body": "ident={{identifier}}&token={{token}}",
        "responseType": "xml",
        "outputs": {
          "stream_url": "link"
        }
      }
    ],
    "result": "{{stream_url}}",
    "headers": {
      "Referer": "https://example.com/",
      "User-Agent": "KELP/1.0",
      "Authorization": "Bearer {{token}}"
    }
  }
}
PoleTypPopis
stepsArray<Step>Pipeline krokov na získanie odkazu.
resultStringŠablóna s premennou, ktorá obsahuje finálnu stream URL. Typicky "{{stream_url}}".
headersObjectNie Extra HTTP hlavičky, ktoré prehrávač pošle pri streamovaní. Podporuje template premenné. Typicky Referer, User-Agent, Cookie alebo Authorization.

StreamUrl pipeline má automaticky k dispozícii:

PremennáHodnota
{{identifier}}Identifikátor súboru zo search výsledkov (hodnota z link/url v itemMapping).
{{token}}Autentifikačný token.

Akcia: http

Vykoná HTTP požiadavku. Najdôležitejšia a najčastejšie používaná akcia.

JSON{
  "action": "http",
  "method": "POST",
  "url": "https://api.example.com/endpoint",
  "contentType": "application/x-www-form-urlencoded",
  "body": "param1={{value1}}¶m2={{value2}}",
  "responseType": "xml",
  "headers": {
    "Authorization": "Bearer {{token}}",
    "X-Custom": "value"
  },
  "outputs": {
    "moja_premenna": "xml_tag_name"
  }
}
ParameterTypPredvolenéPopis
actionString—Musí byť "http".
methodString"GET"HTTP metóda: "GET" alebo "POST".
urlString—URL endpointu. Podporuje interpoláciu.
contentTypeString—Hodnota hlavičky Content-Type.
bodyString—Telo požiadavky (pre POST). Podporuje interpoláciu.
responseTypeString"xml"Formát odpovede: "xml" alebo "json". Ovplyvňuje parsovanie outputs.
headersObject{}Vlastné HTTP hlavičky. Hodnoty podporujú interpoláciu.
outputsObject—Mapovanie: { "nazov_premennej": "cesta_v_odpovedi" }. Pozri XML / JSON parsing.
listElementString—Iba v search: názov elementu, ktorý predstavuje jednu položku v zozname.
itemMappingObject—Iba v search: mapovanie polí položky. Pozri Zoznam výsledkov.

Ak HTTP krok vráti iný status ako 200, celá pipeline zlyhá. Engine nepodporuje presmerovania ani iné 2xx kódy.

Akcia: md5crypt

Vypočíta Unix MD5-crypt hash (formát $1$salt$hash). Používa sa typicky pre staršie API, ktoré vyžadujú tento typ hashovania hesiel.

JSON{
  "action": "md5crypt",
  "input": "{{password}}",
  "salt": "{{salt}}",
  "output": "crypted_password"
}
ParameterTypPopis
inputStringVstupný text (typicky heslo). Podporuje interpoláciu.
saltStringSalt pre hashovanie. Podporuje interpoláciu. Max 8 znakov.
outputStringNázov premennej, do ktorej sa uloží výsledný hash.

Príklad výstupu: $1$abcdefgh$k4x3gHwmKj1vC0B.Xr5M/.

Akcia: sha1

Vypočíta SHA-1 hash vstupného textu.

JSON{
  "action": "sha1",
  "input": "{{crypted_password}}",
  "output": "hashed_password"
}
ParameterTypPopis
inputStringVstupný text. Podporuje interpoláciu.
outputStringNázov premennej pre hex-encoded výstup.

Príklad výstupu: a94a8fe5ccb19ba61c4c0873d391e987982fbbd3

Akcia: md5

Vypočíta MD5 hash vstupného textu.

JSON{
  "action": "md5",
  "input": "{{some_value}}",
  "output": "md5_hash"
}
ParameterTypPopis
inputStringVstupný text. Podporuje interpoláciu.
outputStringNázov premennej pre hex-encoded výstup.

Príklad výstupu: 5d41402abc4b2a76b9719d911017c592

Akcia: assert

Porovná hodnotu runtime premennej s očakávanou hodnotou. Ak sa nezhodujú, pipeline zlyhá a ďalšie kroky sa nevykonajú.

JSON{
  "action": "assert",
  "variable": "login_status",
  "equals": "OK"
}
ParameterTypPopis
variableStringNázov runtime premennej na overenie.
equalsStringOčakávaná hodnota.

Assert je kľúčový na validáciu odpovedí API. Umiestnite ho bezprostredne za HTTP krok, aby ste overili, že operácia (prihlásenie, vyhľadávanie) prebehla úspešne.

Akcia: clear

Odstráni runtime premenné zo stavu enginu.

JSON{
  "action": "clear",
  "variables": ["token", "salt", "crypted_password", "temp_value"]
}
ParameterTypPopis
variablesArray<String>Zoznam názvov premenných na odstránenie.

Typicky sa používa v logout pipeline na vyčistenie tokenov.

Akcia: regex

Extrahuje text z hodnoty premennej pomocou regulárneho výrazu.

JSON{
  "action": "regex",
  "input": "{{_response}}",
  "pattern": "href=\"(https://[^\"]+\\.mp4)\"",
  "group": 1,
  "output": "video_url"
}
ParameterTypPredvolenéPopis
inputString—Vstupný text. Podporuje interpoláciu. Typicky {{_response}}.
patternString—Regulárny výraz (PCRE / Java Regex syntax).
groupInteger1Číslo zachytávacej skupiny na extrakciu.
outputString—Názov premennej pre extrahovanú hodnotu.
optionalBooleanfalseAk je true, zlyhanie kroku nespôsobí zlyhanie celej pipeline — pokračuje sa ďalším krokom. Pozri Voliteľné kroky.

Ak regex nenájde zhodu a krok nie je označený ako "optional": true, pipeline zlyhá. Uistite sa, že vzor zodpovedá formátu odpovede, alebo použite voliteľné kroky s fallbackom.

Voliteľné kroky (optional)

Akýkoľvek krok v pipeline môže byť označený ako voliteľný pridaním "optional": true. Ak voliteľný krok zlyhá, pipeline pokračuje ďalším krokom namiesto okamžitého ukončenia.

Pri akcii regex navyše platí: ak je výstupná premenná (output) už naplnená predchádzajúcim krokom, voliteľný regex sa preskočí. To umožňuje reťazenie fallbackov:

Príklad — reťazenie fallbackov{
  "steps": [
    { "action": "http", "method": "GET", "url": "https://api.example.com/{{identifier}}", "responseType": "json" },
    {
      "action": "regex",
      "input": "{{_response}}",
      "pattern": "\"name\":\\s*\"([^\"]+\\.mp4)\",\\s*\"source\":\\s*\"original\"",
      "group": 1,
      "output": "video_file",
      "optional": true
    },
    {
      "action": "regex",
      "input": "{{_response}}",
      "pattern": "\"name\":\\s*\"([^/\"]+\\.mp4)\"",
      "group": 1,
      "output": "video_file",
      "optional": true
    }
  ],
  "result": "https://example.com/download/{{identifier}}/{{video_file|urlencode}}"
}

V tomto príklade sa najprv hľadá MP4 súbor so source: "original". Ak sa nenájde, druhý regex skúsi nájsť akýkoľvek MP4. Ak prvý regex uspeje, druhý sa preskočí (premenná video_file je už nastavená).

Parameter optional je možné použiť pri všetkých akciách (http, regex, assert atď.), nielen pri regex.

Akcia: set

Priamo nastaví premennú na zadanú hodnotu. Užitočné na zostavenie zložených hodnôt z viacerých premenných alebo nastavenie predvolenej hodnoty.

JSON{
  "action": "set",
  "output": "full_url",
  "value": "https://cdn.example.com/{{path}}/{{filename|urlencode}}"
}
ParameterTypPopis
outputStringNázov premennej, do ktorej sa uloží výsledok.
valueStringHodnota (podporuje interpoláciu a filtre).

Akcia: parallel

Spustí viacero nezávislých krokov súčasne. Všetky vnorené kroky bežia paralelne a výsledok je úspešný, ak uspejú všetky.

JSON{
  "action": "parallel",
  "steps": [
    {
      "action": "http",
      "method": "GET",
      "url": "https://api.example.com/metadata/{{identifier}}",
      "responseType": "json",
      "outputs": { "meta_title": "title" }
    },
    {
      "action": "http",
      "method": "GET",
      "url": "https://api.example.com/files/{{identifier}}",
      "responseType": "json",
      "outputs": { "file_url": "url" }
    }
  ]
}
ParameterTypPopis
stepsArray<Step>Zoznam krokov na paralelné spustenie. Každý krok je štandardná definícia akcie.

Paralelné kroky by nemali od seba navzájom závisieť svojimi výstupmi. Ak krok B potrebuje výstup kroku A, musia bežať sekvenčne (mimo parallel).

Premenné

Addon Engine udržiava runtime slovník premenných (Map<String, String>). Premenné sa plnia z:

  • Credentials — kľúče z auth.fields (napr. username, password, api_key)
  • HTTP outputs — hodnoty extrahované z odpovedí API
  • Crypto kroky — výstupy hashov (md5crypt, sha1, md5)
  • Regex — extrahované podreťazce
  • Automatické — query, page, identifier

Interpolácia {{premenná}}

Kdekoľvek má parameter textovú hodnotu, je možné použiť interpoláciu dvojitými zloženými zátvorkami:

Príklad"url": "https://api.example.com/search?q={{query}}&token={{token}}"
"body": "username={{username}}&password={{hashed_password}}"
"input": "{{crypted}}"

Engine nahradí každý výskyt {{nazov}} aktuálnou hodnotou zo slovníka premenných. Ak premenná neexistuje, nahradí sa prázdnym reťazcom.

Filtre {{premenná|filter}}

Za názov premennej je možné pridať filter oddelený zvislou čiarou (|), ktorý transformuje hodnotu pred vložením:

Príklad"url": "https://api.example.com/search?q={{query|urlencode}}"
"body": "token={{token|base64}}"
"header": "{{api_key|uppercase}}"
FilterPopisPríklad vstupu → výstupu
urlencodeURL-enkódovanie (percent-encoding). Odporúčané pre {{query}} v URL.Slovenský film → Slovensk%C3%BD%20film
base64Base64 enkódovanie.hello → aGVsbG8=
lowercasePrevod na malé písmená.HELLO → hello
uppercasePrevod na veľké písmená.hello → HELLO
trimOdstráni biele znaky na začiatku a na konci. hello → hello
htmldecodeDekóduje HTML entity.&amp; &lt; → & <
lengthDĺžka reťazca (výstup je číslo).hello → 5
reverseObráti znaky v reťazci.hello → olleh
timestampVráti aktuálny Unix timestamp v sekundách (ignoruje hodnotu premennej).→ 1741700000
timestamp_msVráti aktuálny Unix timestamp v milisekundách.→ 1741700000000

Ak filter nie je rozpoznaný, hodnota sa vloží bez transformácie.

{{timestamp_ms}}VždyAktuálny Unix timestamp v milisekundách.

XML parsing

Pri "responseType": "xml" engine extrahuje hodnoty pomocou názvov XML tagov.

XML odpoveď<response>
  <status>OK</status>
  <token>abc123xyz</token>
  <user_id>42</user_id>
</response>
outputs"outputs": {
  "status_var": "status",
  "token": "token",
  "uid": "user_id"
}

Výsledok: status_var = "OK", token = "abc123xyz", uid = "42"

XML parser podporuje tagy s atribútmi — napr. <file id="123">...</file> sa nájde pri hľadaní tagu file. Na extrakciu atribútov použite notáciu tag@attr v mapovaní (pozri nižšie).

Na extrakciu atribútov z XML tagov použite notáciu tag@atribút:

XML s atribútmi<files>
  <file id="abc123" type="video">Film.mp4</file>
  <file id="def456" type="subtitle">Film.srt</file>
</files>
itemMapping"itemMapping": {
  "title": "file",
  "link": "file@id",
  "type": "file@type"
}

Výsledok: link = "abc123", type = "video". Notácia @attr (bez tagu) extrahuje atribút z nadradeného elementu.

JSON parsing

Pri "responseType": "json" engine používa bodkovú notáciu na navigáciu v JSON štruktúre.

JSON odpoveď{
  "status": "ok",
  "data": {
    "token": "xyz789",
    "user": {
      "id": 42,
      "name": "Ján"
    }
  }
}
outputs"outputs": {
  "my_token": "data.token",
  "user_name": "data.user.name",
  "user_id": "data.user.id"
}

Výsledok: my_token = "xyz789", user_name = "Ján", user_id = "42"

Na prístup k prvkom poľa použite číselný index alebo hranatú notáciu:

JSON cesta s poľom"outputs": {
  "first_item": "results[0].name",
  "first_item_alt": "results.0.name"
}

Na filtrovanie poľa podľa hodnoty kľúča použite [?(@.key=='value')]:

JSON cesta s filtrom"outputs": {
  "video_file": "files[?(@.source=='original')].name"
}

Filter prejde pole files a vráti prvý prvok, kde source je "original", následne z neho extrahuje name.

V itemMapping search krokov možno takisto použiť vnorené cesty: "title": "metadata.title" alebo "id": "files[0].id".

Zoznam výsledkov (List parsing)

Pre search pipeline musí HTTP krok s listElement identifikovať opakujúce sa prvky v odpovedi:

XML zoznam

XML odpoveď<response>
  <status>OK</status>
  <file>
    <name>Film.2024.SK.mkv</name>
    <size>1536000000</size>
    <ident>abc123</ident>
  </file>
  <file>
    <name>Film.2024.EN.mp4</name>
    <size>987000000</size>
    <ident>def456</ident>
  </file>
</response>
Search krok{
  "action": "http",
  "method": "POST",
  "url": "https://api.example.com/search",
  "body": "q={{query}}&token={{token}}",
  "responseType": "xml",
  "listElement": "file",
  "itemMapping": {
    "title": "name",
    "size": "size",
    "link": "ident"
  }
}

Engine nájde všetky <file>...</file> bloky a z každého extrahuje name, size a ident podľa mapovania.

JSON zoznam

JSON odpoveď{
  "status": "ok",
  "results": [
    { "title": "Film.2024.SK.mkv", "filesize": 1536000000, "id": "abc123" },
    { "title": "Film.2024.EN.mp4", "filesize": 987000000, "id": "def456" }
  ]
}
Search krok{
  "action": "http",
  "method": "GET",
  "url": "https://api.example.com/search?q={{query|urlencode}}",
  "responseType": "json",
  "listElement": "results",
  "itemMapping": {
    "title": "title",
    "size": "filesize",
    "link": "id"
  }
}

listElement pri JSON odpovedi je cesta (bodková notácia) k poľu objektov. Pri každom objekte sa kľúče z itemMapping použijú na nájdenie príslušnej hodnoty.

Addon Types (typy)

HodnotaPopis
"api"Údaje sa získavajú cez štruktúrované API (REST, XML-RPC, GraphQL...).
"scraper"Údaje sa získavajú parsovaním HTML stránok (pomocou regexu).

Typ doplnku sú informatívne metadáta — nemá vplyv na správanie enginu. Engine vykonáva kroky rovnako bez ohľadu na typ.

Chybové stavy

Engine môže zlyhať v niekoľkých situáciách:

SituáciaČo sa stane
HTTP krok vráti iný status ako 200Pipeline sa zastaví, krok vráti false.
Assert zlyhá (hodnota != expected)Pipeline sa zastaví, celý flow vráti false.
Regex nenájde zhoduPipeline sa zastaví, krok vráti false.
Neznáma akciaPipeline sa zastaví, vypíše sa varovanie do konzoly.
Timeout HTTP požiadavkyEngine zachytí výnimku, krok vráti false.
Neplatný JSON súborImport zlyhá, zobrazí sa chybová hláška.
Duplicitné addon IDImport je odmietnutý s upozornením.

Obmedzenia a limity

  • Iba HTTP GET a POST — iné metódy (PUT, DELETE, PATCH) nie sú podporované.
  • Žiadny JavaScript — doplnok nemôže spúšťať JS kód (na rozdiel od doplnkov do prehliadača).
  • XML menné priestory — parser podporuje tagy s atribútmi, ale nepodporuje XML namespaces (napr. ns:tag).
  • JSONPath bez wildcards — nemožno použiť data.*.name. Podporované sú indexy [0] a filtre [?(@.key=='val')].
  • MD5-crypt salt max 8 znakov — dlhšie salty sú orezané.
  • Žiadne cookies — engine automaticky nespravuje cookies. Tokeny je nutné odovzdávať explicitne.
  • Žiadne presmerovania — HTTP klient nenasleduje 3xx redirecty automaticky v kontexte parsovania odpovedí.
  • Premenné sú iba reťazce — všetky runtime hodnoty sú stringy bez číselných operácií.
  • Jedna search stránka = jeden HTTP krok s listElement — nemožno kombinovať výsledky z viacerých volaní v jednej pipeline (možno však použiť parallel pre nezávislé volania).

Právne upozornenie

Aplikácia KELP neobsahuje žiadny obsah ani prístup k akémukoľvek úložisku. Všetka funkcionalita úložísk je zabezpečená výhradne doplnkami, ktoré si používateľ importuje na vlastnú zodpovednosť. Vývojár aplikácie neposkytuje, neschvaľuje ani nekontroluje žiadne doplnky.

Inštaláciou akéhokoľvek doplnku preberáte plnú zodpovednosť za jeho použitie. Uistite sa, že dodržiavate platné zákony vašej krajiny, najmä v oblasti autorských práv. Vývojár nenesie žiadnu zodpovednosť za obsah sprístupnený prostredníctvom doplnkov tretích strán.
